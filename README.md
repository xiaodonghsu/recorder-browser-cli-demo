# VoiceHub Browser · 蓝牙录音卡测试台

纯浏览器 BLE + GATT 测试项目，使用 JavaScript 实现录音卡私有协议。**蓝牙连接、设备控制、文件下载和实时音频接收均由浏览器直接完成，无 Python、WebSocket 网关或蓝牙后台服务。** 构建产物是可以部署到 HTTPS 静态托管的 HTML / CSS / JS。

参考协议与行为来源：[recorder-python-cli-web-demo](https://github.com/xiaodonghsu/recorder-python-cli-web-demo)，核对版本 `789b88a388bdc12ade39a71bce20b63b7aec1b9c`。本项目独立实现浏览器传输和会话层，没有运行或引入参考项目的 Python 程序。

## 启动

开发环境需要 Node.js 20.19+ 或 22.12+（推荐当前 LTS）：

```sh
npm ci
npm run dev
```

用桌面 **Chrome / Edge** 打开 **http://127.0.0.1:5186**，开启系统蓝牙和录音卡电源，点击「连接蓝牙录音卡」，在浏览器选择器中授权设备。端口若已占用，可使用 `npm run dev -- --port 5187`。

操作顺序为 **连接录音卡 → 连接区下方的「设备授权」→ 获取设备信息**。授权输入框已按指定预填默认 AuthKey，可根据设备修改；采用密码输入框显示，不写入日志或浏览器存储。连接后仅订阅通知，不主动查询设备信息；电量通知仍可正常显示。点击「授权并获取设备信息」，收到 `0-51 result=0` 后才自动查询；也可在授权后点击「读取设备信息」刷新。授权失败或超时不会触发查询，断开后需重新授权。

## 功能

- BLE 选择设备、连接、断开、兼容扫描（广播不包含 AE20 时可用）。
- 电量（包含 110 充电状态）、容量、固件、时间同步、AuthKey 鉴权。
- 设备录音的开始、暂停、继续、保存；录音状态、时长、文件名与增益查询、增益设置。
- 实时推流的开始、暂停、继续、停止；实际接收字节、载荷包数、传输速率与 CRC 错误统计。
- 原始音频载荷导出、保留包边界与时间的 `.vhstream` 捕获文件、可选 WebCodecs Opus 实时试听与已解码 PCM 的 WAV 导出。
- 文件列表、候选文件名回退下载、取消、在同页缓存上的续传、按偏移分段下载、原始片段导出。
- 标准 WAV 结构与长度校验、浏览器试听、保存到本地、带确认的单文件删除。
- 原始 TYPE / CMD / HEX 参数调试、会话日志过滤与导出、固件协议兼容设置。
- 会话日志在桌面右侧固定显示并独立滚动，窄屏固定于底部；切换菜单和滚动操作区不会重建或清空日志。按钮点击记录带编号的 `ACTION`，异步操作的处理结束、错误与确认/取消可按相同编号追踪，并保留设备 TX/RX。密钥及原始命令输入内容不会写入点击日志。

## 浏览器和部署

Web Bluetooth 要求安全上下文及用户点击触发设备选择器。本地使用 `localhost` / `127.0.0.1`，部署时使用 **HTTPS**。手机通过局域网 `http://电脑IP` 访问通常不满足要求。Windows/macOS 上优先使用支持 Web Bluetooth 的 Chrome 或 Edge；iOS Safari、Firefox 等不能假定支持，页面会检测 `navigator.bluetooth` 并显示提示。移动端界面适配不等于所有移动浏览器都支持蓝牙。参见 [Chrome 官方 Web Bluetooth 文档](https://developer.chrome.com/docs/capabilities/bluetooth)。

```sh
npm run build
npm run preview
```

将 `dist/` 部署到 HTTPS 静态站点即可，用户端只需浏览器与系统蓝牙。Node/Vite 仅用于开发、构建或本地静态预览，不参与蓝牙通信。项目无远程字体、CDN 或运行时网络依赖。页面保持在前台；锁屏、后台节流、系统休眠和射频丢包可能中断音频接收。

### Nginx 根目录或子目录部署

Vite 已配置 `base: "./"`，构建产物引用 `./assets/...`，同一份 `dist/` 可部署到站点根目录或任意子目录，无需重新指定目录前缀。

例如将 `dist/` 的内容复制到 `/var/www/voicehub/`，在已有的 HTTPS `server` 中添加：

```nginx
location = /voicehub {
    return 301 /voicehub/;
}

location /voicehub/ {
    root /var/www;
    index index.html;
    try_files $uri $uri/ =404;
}
```

访问 `https://你的域名/voicehub/`。子目录入口需要保留结尾 `/`，以便浏览器正确解析相对资源地址；上面的重定向会自动补全。本项目使用 hash 导航（如 `/voicehub/#live`），不需要额外的 SPA 路由回退。根目录部署时，将 `dist/` 内容放到 Nginx 的站点 `root` 下即可。

## 真机联调步骤

1. 先关闭可能占用录音卡的 App 或其他 BLE 程序，打开录音卡并连接。
2. 如找不到设备，勾选「兼容扫描」，手动选择已知录音卡；选到没有 AE20 服务的设备会报错。
3. 在连接区下方核对 AuthKey，点击「授权并获取设备信息」，等待授权通过后自动读取设备信息。
4. 开始设备录音 → 暂停 → 继续 → 保存，确认设备实际状态更新。
5. 「录音文件」获取列表，点击录音行的「下载」立即发送请求并接收文件，校验 WAV 后可试听并保存；自定义文件名和分段偏移可在下方设置后点击「下载文件」。
6. 「实时音频」开始推流，观察载荷数量及速率，再暂停/继续/停止，导出 `.vhstream` 以核对真实音频包格式。
7. 只有确认每个 `1-1` 载荷是一个标准 Opus 包后，再打开实验性试听。

**当前已完成协议测试、浏览器端到端测试和真机下载样本的解码验证，尚未完成真实录音卡连接联调。** 自动化测试不能证明适配器的 MTU、固件鉴权或实际无线吞吐满足要求。

## 协议兼容与限制

### BLE 与帧格式

| 用途     | UUID                                   |
| -------- | -------------------------------------- |
| 业务服务 | `0000ae20-0000-1000-8000-00805f9b34fb` |
| 写入     | `0000ae21-0000-1000-8000-00805f9b34fb` |
| 主通知   | `0000ae22-0000-1000-8000-00805f9b34fb` |
| 按键通知 | `0000ae23-0000-1000-8000-00805f9b34fb` |

帧为 `[5A][SEQ][CRC:2B LE][LEN:2B LE][TYPE][CMD][PARAMS...]`，CRC-16/XMODEM 覆盖 `LEN + DATA`。AE22/AE23 使用独立的流式缓存，支持通知半帧、多帧、噪声重同步、CRC 错误恢复。TYPE-only ACK 不会被当成业务成功。

写入和请求分别排队，避免 GATT 并发操作及同类型应答争用。断开会拒绝等待中的请求，移除通知监听，清除设备状态；已接收音频和下载片段仍可导出。

### 参考项目里的长度差异

参考仓库 README、协议表格、厂家页面和当前 Python 常量不完全一致，不能把所有设备都当成同一种布局：

| 字段               | 默认                              | 可选兼容                                      |
| ------------------ | --------------------------------- | --------------------------------------------- |
| 文件列表条目       | 根据每帧 count 与载荷长度精确检测 | 28B（20B 名字）/ 33B（25B 名字）              |
| 导入请求文件名字段 | 29B（41B 完整请求，参考 Python 当前代码） | 24B（早期真机示例）/ 25B |
| 设备录音应答       | `3-2/4/6/8`                       | 设置中启用旧版 `3-0` 通用应答，并查询实际状态 |

文件名超长会报错，**不静默截断**。点击右上角齿轮切换长度。删除使用列表中保留的原始完整条目。列表在最后一次通知后空闲 1.5 秒会兼容收尾，明确记录「可能不完整」；总超时 15 秒，不将无应答宣称为设备确认的空列表。

导入、鉴权等请求均 **一次 GATT 整帧写入，不切成 20B 小块**。Web Bluetooth 不暴露 MTU 查询或手动协商；若系统/适配器无法整帧写入 36/40/41 字节，本页报错，需要重新连接或更换支持环境，应用不能用假分包规避。默认优先请求 `.opus`，其次尝试 `.wav` 和列表原始名称；手动输入文件名时按输入值请求。候选名只在设备明确返回 `2-5 code=1` 且尚未接收数据时回退；已有数据或超时不会自动换名。

下载空闲超时 12 秒；取消/超时会发送 `2-7` 请求并等待 `2-11`。未确认终止的会话要求断开重连，防止旧数据混入新下载。续传仅允许同一设备、同名文件、同页保留的完整前缀；刷新页面不能恢复。续传仍需保证录音卡上的源文件没有变化。手工偏移和分段结果标为 `.part.bin`，不会伪装成完整 WAV。

### 下载的 Opus 与 FFmpeg

真机样本 `tests/note_2026-11-02-07-46-02.opus` 是 **40 字节/包、20 ms/包的标准 Opus 裸流**，共 1005 包、20.1 秒，单声道 SILK wideband。它没有 Ogg 文件头，直接交给 FFmpeg 会报 `Invalid data found when processing input`。开头 `4B 41` 是合法 Opus TOC 与帧计数/填充标志，不应删除为所谓私有包头。

完整下载符合此格式时，页面自动补上 Ogg 封装，提供试听和 `.ogg.opus` 保存，同时可单独保存原始裸流。仅改变容器，编码包逐字节保留；其他格式和未完成片段不会猜测封装。裸流没有编码器延迟元数据，因此封装的 pre-skip 设为 0，保留全部解码样本，不能恢复精确的原始裁剪位置。

已经下载的同格式文件可离线修复（输出文件必须不存在）：

```sh
node scripts/wrap-opus.js tests/note_2026-11-02-07-46-02.opus tests/note_2026-11-02-07-46-02.ogg.opus
ffmpeg -i tests/note_2026-11-02-07-46-02.ogg.opus -ar 16000 -ac 1 tests/note_2026-11-02-07-46-02.wav
```

### 实时音频格式

参考协议只说明为「OPUS 系码流」，没有规定每个 BLE 业务载荷的内部封装。**接收到压缩字节不等于已经可以播放或转写。** 默认只接收、统计并保留原始数据，图表展示实际字节传输速率；不会将压缩字节伪造为 PCM 波形。

实验性试听通过浏览器 `AudioDecoder` 解码，前提是**每个 TYPE=1 / CMD=1 的 body 正好是一个完整标准 Opus 包，单声道**。解码按 TOC 计算包时长，Web Audio 播放；失败时关闭试听并继续接收原始流。私有包头、包内多包、跨载荷分片或不同编码需要根据真机抓包适配 `src/audio.js` 的入口。没有引入 Python、FFmpeg 服务、ASR 服务或云端密钥。当前未实现语音转文字。

- `.opus.bin`：按接收顺序拼接的音频 body，**不是保证可播放的 Ogg Opus 文件**。
- `.vhstream`：8B ASCII `VHSTREAM` + 4B LE JSON 长度 + UTF-8 JSON 元数据（版本、文件名、相对时间/包长）+ 重复的 `[4B LE 包长][原始载荷]`。保留包边界便于下一步适配。
- 已解码 WAV：只包含启用试听期间成功解码的 PCM，48 kHz、16 bit、单声道。

测试项目使用内存缓存：单次文件接收上限 256 MiB、实时压缩载荷 128 MiB 或 200000 包、解码 PCM 64 MiB。达到限制会停止相应接收/试听并保留已有数据，可分段下载或导出后开启新会话。刷新/关闭页面会丢失未导出的缓存。设备录音（TYPE=3）与实时推流（TYPE=1）是两套独立控制；断开蓝牙不能假定停止设备本体录音。

## 页面提示 Web Bluetooth 不可用时

浏览器版本够新，不代表当前网址能使用 Web Bluetooth。先看「协议调试 → 浏览器环境诊断」：

- `secureContext: false`：当前来源不安全。`http://192.168.x.x:端口` 等普通 HTTP 局域网 IP 不在本地回环例外内；在运行项目的同一台电脑上改用 `http://127.0.0.1:5186/` 或 `http://localhost:5186/`。另一台电脑/手机上的 localhost 指向那台设备本身，跨设备访问需部署受信任的 HTTPS。
- `secureContext: true` 且 `apiExposed: false`：检查浏览器平台支持、启动参数、扩展或管理配置。不能仅凭 API 缺失认定蓝牙硬件损坏。
- `bluetoothAllowed: false`：检查 Permissions Policy 和 iframe 授权，在独立标签页打开页面重试。
- `apiExposed: true` 且 `adapterAvailable: false`：API 存在，但浏览器当前报告蓝牙不可用；检查系统蓝牙、适配器及浏览器限制。此结果不能单独区分具体原因。

普通 HTTP 的不安全来源会隐藏 `navigator.bluetooth`，因而旧提示「当前浏览器不支持」过于笼统。当前版本已按安全上下文、Permissions Policy 与 API 暴露情况分别提示。设备权限通常在 API 调用时才拒绝，不应与 API 缺失混为一谈。无需为了本机 localhost 使用而打开实验性 flags，也不建议全局关闭浏览器安全限制。

参考：[Chrome 安全上下文要求](https://developer.chrome.com/docs/capabilities/bluetooth#security_requirements)、[Edge Web Bluetooth 管理策略](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/defaultwebbluetoothguardsetting)。
