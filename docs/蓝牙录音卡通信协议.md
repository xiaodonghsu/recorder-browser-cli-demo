# 蓝牙录音卡通信协议（浏览器实现版）

更新日期：2026-11-19。适用于当前 VoiceHub Browser。

2026-11-21 修正：根据 PNote.getSn() 的帧构造和应答解析，设备 SN 通过 `0-12/0-13` 读取。

本文依据现有代码整理，参考[原协议](https://github.com/xiaodonghsu/recorder-python-cli-web-demo/blob/master/docs/%E5%8D%8F%E8%AE%AE.md)，修正其中的长度、流程和兼容性描述。代码依据：`src/protocol.js`、`src/recorder.js`、`src/audio.js`、`src/ogg-opus.js`。

当前已有协议单元测试、模拟设备测试和真机下载音频样本验证，尚未完成本浏览器项目的真实设备连接联调。默认参数代表当前实现，不代表所有固件均已验证。

## 1. 连接与传输

浏览器作为 BLE 主机，直接连接录音卡，不经过 HTTP、WebSocket 或 Python 服务。

| 用途 | UUID 短值 | 方向 |
| --- | --- | --- |
| 业务服务 | AE20 | — |
| 命令写入 | AE21 | 浏览器 → 设备 |
| 主通知 | AE22 | 设备 → 浏览器 |
| 按键通知 | AE23 | 设备 → 浏览器 |

完整 UUID 为 `0000xxxx-0000-1000-8000-00805f9b34fb`，将 `xxxx` 替换为表中短值。

连接后先订阅 AE22，再尝试订阅 AE23；AE22 失败则连接失败，AE23 失败仅警告。两个通知通道分别缓存、组帧，不能混用缓存。当前实现按 TYPE/CMD 处理两个通道的有效帧，不硬性限定业务应答只能来自 AE22。

AE21 优先使用无响应写入，不支持时使用有响应写入。每个协议帧一次完整写入，应用层不拆包。浏览器不提供手动查询或设置 MTU 的接口；整帧写入失败应报错。

## 2. 通用帧

| 偏移 | 长度 | 字段 | 含义 |
| --- | --- | --- | --- |
| 0 | 1B | MAGIC | 固定 `0x5A` |
| 1 | 1B | SEQ | 发送序号，0～255 循环 |
| 2 | 2B | CRC | 小端，CRC-16/XMODEM |
| 4 | 2B | LEN | 小端，DATA 字节数 |
| 6 | LEN | DATA | `TYPE:1B + CMD:1B + 参数` |

完整帧长度为 `6 + LEN`。当前编码器与解析器接受 `LEN=1～8192`；这是本项目限制。

- CRC 覆盖 `LEN 原始两字节 + DATA`，不包含 MAGIC、SEQ、CRC 自身。多项式 `0x1021`，初值与异或输出均为 0，不反射；校验向量 `123456789 → 0x31C3`。
- 一个通知可能包含半帧或多帧，必须按 LEN 重组后校验 CRC；损坏帧丢弃并重新寻找帧头。
- DATA 只有 TYPE 一个字节时视为 ACK，不表示业务操作成功；TYPE=3 仍是录音控制族。
- 下文 `0-50` 表示 `TYPE=0、CMD=50`；命令号用十进制，HEX 示例用十六进制。
- 应答按 `(TYPE, 应答CMD)` 匹配，不按 SEQ 匹配。普通请求串行等待，默认超时 5 秒；不能把所有命令都套用“CMD+1”。

## 3. 设备信息与鉴权（TYPE=0）

以下参数均为 DATA 中 TYPE、CMD 后的内容；“无”表示无参数。

| 请求 → 应答 | 功能 | 请求参数 | 应答内容 |
| --- | --- | --- | --- |
| 0-0 → 无专用应答 | 校时 | 年:2B LE，月/日/时/分/秒各1B | 使用浏览器本地日历时间，共7B |
| 0-1 → 0-2 | 容量 | 无 | 剩余:4B LE + 总量:4B LE |
| 0-3 → 0-4 | 电量 | 无 | 1B，0～100；110 显示充电中 |
| 0-10 → 0-11 | 固件版本 | 无 | UTF-8 文本，遇 NUL 结束，不强制6B |
| 0-12 → 0-13 | 设备 SN | 无 | 全部载荷为 UTF-8 SN 字符串，无状态码前缀 |
| 0-50 → 0-51 | AuthKey 认证 | 32B 密钥 | 首字节0成功，非0失败；空应答失败 |

容量当前按数值乘 `1024` 换算为字节；原协议另有 8KB 单位描述，实际单位待目标固件确认。

SN 使用 `PNote.getSn()` 对应的只读查询：通过 AE20 服务的 AE21 特征单次写入 `TYPE=0、CMD=12`，无参数，共 8 字节。SEQ=0 时完整帧为 `5A 00 E4 2C 02 00 00 0C`；实际 SEQ 随会话递增。AE22 通知返回 `TYPE=0、CMD=13`，将帧中偏移 8 开始的全部 SN 载荷按 UTF-8 解码，不将首字节当状态码，也不截取固定长度。授权成功后及手动刷新时读取；空应答、写入失败或 5 秒超时时显示“未知”并继续读取其他信息，断开连接清除 SN，迟到应答不恢复旧状态。此查询无需标准 `180A/2A25` 服务，且与 `0-50/0-51` 的 AuthKey 认证不同。

AuthKey 输入为64位十六进制字符，可带 `0x`/`0X`，允许首尾空白，不允许内部空白。转为32字节后发送，完整认证帧40B。只有收到 `0-51 result=0` 才设置已授权；断开即清除授权状态。

当前页面流程：连接 → 用户点击授权 → 认证成功后读取设备信息；常规业务按钮也要求已授权，原始命令入口只要求已连接。`refresh()` 本身检查授权；其他底层发送方法没有统一鉴权拦截，不能据此断言设备已强制保护全部命令。超时只表示结果未确认，不能直接认定固件不支持，也不会自动降级为认证通过。

参考协议还列出以下命令，当前仅可经原始命令入口发送，没有专用业务流程：

| 请求 → 应答 | 功能 | 参数 / 应答 |
| --- | --- | --- |
| 0-52 → 0-53 | 设置 AuthKey | 32B 新密钥 / 1B结果 |
| 0-54 → 0-55 | 解除绑定 | 无 / 1B结果 |

这些扩展的固件支持及设置/解绑后的行为需单独验证。设置或解绑超时不能盲目重发，也不能仅凭旧密钥认证失败断言操作成功。密钥在协议载荷中是明文；日志应脱敏。当前页面预填测试默认值，仅作为测试台行为，不作为业务系统的密钥分发方式。

## 4. 设备录音控制（TYPE=3）

此族控制设备内录音文件；TYPE=1 控制实时音频推送，两者分别操作。

| 请求 → 应答 | 功能 | 请求参数 | 应答内容 |
| --- | --- | --- | --- |
| 3-1 → 3-2 | 开始录音 | 无 | 1B，1成功，其他值或空应答失败 |
| 3-3 → 3-4 | 结束并保存 | 无 | 同上 |
| 3-5 → 3-6 | 暂停录音 | 无 | 同上 |
| 3-7 → 3-8 | 继续录音 | 无 | 同上 |
| 3-19 → 3-20 | 查询状态 | 无 | 1B：1录音中、2未录音、3暂停 |
| 3-21 → 3-22 | 查询时长/大小 | 无 | 时长:2B LE + 大小:4B LE |
| 3-23 → 3-24 | 当前文件名 | 无 | UTF-8，遇 NUL 结束 |
| 3-25 → 3-26 | 查询增益 | 无 | 1B：1低、2中、3高 |
| 3-27 → 3-28 | 设置增益 | 1B，1～3 | 1B，0成功；随后重新查询增益 |

录音控制成功后还需发送 `3-19` 确认状态。不要混淆录音操作的成功值1和增益设置的成功值0。

设备主动上报 `3-1/3/5/7` 时，当前实现分别更新为录音中/未录音/暂停/录音中。默认不接受 `3-0` 作为控制结果；开启旧版兼容后可接受，但仍必须查询真实状态，不能将其当作标准成功结果。

## 5. 文件列表与下载（TYPE=2）

| 命令 | 方向 | 功能 / 参数 |
| --- | --- | --- |
| 2-0 | 浏览器 → 设备 | 请求列表，无参数 |
| 2-1 | 设备 → 浏览器 | `count:4B BE + count个条目` |
| 2-18 | 设备 → 浏览器 | 列表结束，首字节0表示完成 |
| 2-2 | 浏览器 → 设备 | 下载：`offset:4B LE + 定长文件名` |
| 2-3 | 设备 → 浏览器 | 开始下载，内容为实际文件名 |
| 2-4 | 设备 → 浏览器 | 文件字节片段，按接收顺序拼接 |
| 2-5 | 设备 → 浏览器 | 下载结束：0完成、1不存在、2偏移过大、3其他停止；空内容按3处理 |
| 2-7 → 2-11 | 请求 → 应答 | 终止下载，无参数 |
| 2-8 → 2-13 | 请求 → 应答 | 删除：发送列表原始条目；应答首字节0成功 |
| 2-12 | 浏览器 → 设备 | 分段下载：`start:4B LE + end:4B LE + 定长文件名`；后续同2-3/4/5 |

参考协议的 `2-9/2-10` 为删除全部请求/结果，当前没有专用入口与结果处理。

### 5.1 列表条目

count 是本帧条目数。每条结构如下，两个整数均为大端：

| 字段 | 长度 | 当前解释 |
| --- | --- | --- |
| duration | 4B | 录音秒数；部分固件是否为时间戳待确认 |
| size | 4B | 设备中存储的文件字节数 |
| name | 20B或25B | UTF-8，NUL填充；可能截断文件名 |

因此条目长度分别是28B或33B。默认按 `(应答内容长度-4)/count` 自动检测，只接受精确匹配的两种布局；count=0时内容必须恰好4B。删除时发送保存的原始28B/33B条目，不重新拼接文件名。

列表可跨多帧累积，收到 `2-18` 且状态0才是明确完成。当前兼容策略为发送成功后、或最后一帧列表后空闲1.5秒收尾，并提示“可能不完整”；即使返回空列表也不代表设备明确确认无文件。总等待上限15秒。

### 5.2 下载文件名与长度

下载文件名字段与列表文件名字段是独立配置，不应混为同一长度。

| 下载文件名字段 N | 普通下载完整帧 | 分段下载完整帧 | 用途 |
| --- | --- | --- | --- |
| 29B | 41B | 45B | 当前 Recorder / 页面默认 |
| 24B | 36B | 40B | 兼容早期请求样例 |
| 25B | 37B | 41B | 兼容参考文档另一布局 |

普通下载长度为 `6+2+4+N`；分段下载为 `6+2+8+N`。底层 `importParams()` 辅助函数默认 N=24，但 Recorder 会显式传入设置值，默认 N=29。

文件名按 UTF-8 字节计长，不足 N 补0，恰好 N 时不追加 NUL，超长直接报错，不截断。偏移为0～4294967295的整数字节位置；分段要求 end>start，当前进度按 end-start 计算，目标固件的结束边界语义仍需验证。

默认候选顺序为 `.opus` → `.wav` → 列表原名，先移除已有 wav/opus/mp3 扩展名或末尾句点，再补扩展名。手工指定名称按输入发送；只有收到 `2-5 code=1`、尚无数据且 offset=0时才自动换候选名。超时不换名。

### 5.3 接收、取消与续传

1. 建立本地会话后整帧发送 `2-2` 或 `2-12`；`2-3` 用于记录设备文件名，当前实现也允许直接接收 `2-4`。
2. 拼接所有 `2-4` 内容，不包含通用帧头和 TYPE/CMD；收到 `2-5 code=0` 才表示设备报告传输完成，文件格式需另行检查。
3. 下载空闲12秒、用户取消或其他未确认结束的错误会保留已有数据，并发送 `2-7`，等待 `2-11` 最多3秒。未确认终止则必须重连后才能再次下载。
4. 续传使用已接收字节数作为 offset，仅拼接同设备、同文件、同页保留的完整前缀，且源文件应保持不变。手工偏移/分段结果标为片段，不作为完整文件。

列表 size 不能作为转码后 WAV 的精确大小；当前对 `.wav` 请求按 `duration×32000+44` 估算进度，其他请求按列表 size 估算，均不作为完成判据。WAV 需检查 RIFF/WAVE、fmt/data 块和声明长度；实际格式以内容为准，不能只看扩展名。

## 6. 实时音频（TYPE=1）

| 命令 | 方向 | 内容 |
| --- | --- | --- |
| 1-0 | 浏览器 → 设备 | 开始推流，无参数 |
| 1-0 | 设备 → 浏览器 | 本次推流文件名 |
| 1-1 | 设备 → 浏览器 | 音频载荷 |
| 1-2 | 浏览器 → 设备 | 停止推流，无参数 |
| 1-3 | 浏览器 → 设备 | 1B：1暂停，0继续 |
| 1-4 | 设备 → 浏览器 | 1B：0推流中、1暂停、2停止 |

写入成功只表示命令已发送。开始后等待文件名或音频数据，最终状态参考设备通知。当前项目没有语音识别接口，“实时推流”不等于已经完成文字转写。

实时保存每个 `1-1` 的完整内容及包长、接收时间。实验性 WebCodecs 试听要求一个 `1-1` 恰好是一个标准 Opus 包；该条件需要真机验证，不能套用下载样本的固定包长。

已验证的下载样本 `tests/note_2026-11-02-07-46-02.opus` 为40B/包、20ms/包的单声道 Opus 裸流，共1005包、20.1秒。它缺少 Ogg 容器；`4B 41` 属于合法 Opus 包结构，不应删除。当前仅对完整且匹配已知包结构的下载结果补 Ogg 封装，编码包不变，pre-skip=0；不能据此推广到所有固件或实时载荷。

浏览器实时解码与导出 WAV 使用48kHz、单声道、16bit PCM；它与设备可能输出的16kHz WAV 是不同路径。`.vhstream` 是本项目本地捕获格式，不是 BLE 命令：`VHSTREAM:8B + JSON长度:4B LE + UTF-8 JSON + 重复[载荷长度:4B LE + 载荷]`，JSON保存包长和相对接收时间（毫秒）。

## 7. 本版主要修正

- 统一文件列表计算：4+4+20=28B，4+4+25=33B。
- 下载请求按配置计算长度，明确当前默认41B及36B/37B兼容布局。
- 对齐当前候选名顺序、列表空闲收尾、下载终止确认和续传条件。
- 区分录音控制、实时推流、音频编码与容器，补充已验证的 Opus 样本结论。
- 将认证超时写为“结果未确认”，移除自动认定不支持及凭旧密钥失效推断设置/解绑成功的结论。
- 区分现有专用功能、原始命令可发送的参考扩展和仍需真机确认的固件行为。
